# Tumoflip Dev 009-015

## Changes

- Record one redacted software-fault or watchdog event in RTC backup registers
  across reboot. The entry exposes only a fault class, sanitized app-id prefix,
  sequence, and build prefix through `tumocrash show` and the Runtime App Bridge.
- Keep the existing fault popup. Ordinary reboot and normal application exit
  must not create a crash entry. Clearing requires `tumocrash clear` or an
  explicit Companion action.
- Repair host test discovery for the CUID loading and feature-size regressions.

F7 API remains **88.14**. No FW Packages API refresh or SD package migration is
required. No saved Sub-GHz recordings, NFC files, or user settings are removed.

## Validation and installation

The exact 009-015 source passed 1031 host tests, the F7 updater and FAP build,
APPCHK, Sub-GHz feature-import validation and native Weather Editor rendering.
The release validator accepted the updater and SD manifest: physical C2 gap
12,288 bytes, updater 120,065 / 131,072 bytes, API 88.14. Back up `/int` and
important SD files before installing this Dev build.

Hardware acceptance is **not complete**. On the installed build, first verify
ordinary boot, repeated application launch/exit, BLE App Bridge, and that no
crash record appears after a normal reboot. Controlled fault and watchdog tests
should be performed only on a test Flipper; confirm one record appears and the
existing fault popup still works. TumoCompanion 1.11.25 can display and clear
the record, but older Companion versions remain compatible.

This is a Dev prerelease for functional testing, not a stable release.

# Tumoflip Dev 009-017

## Changes

- Fiat V2: check every capture-format write, including Raw, Serial, Cnt,
  Hop and Btn. Invalid input leaves the previously loaded frame intact.
  ProtoPirate FAP version advances to **3.2.1** without replacing Tumoflip's
  existing radio ownership or feature gates.
- Renault V1: add a **receive-only** Europe Protocol Pack plugin with bounded
  Manchester decoding, 104-bit frame/header/XOR validation and duplicate-frame
  filtering. Save the complete payload, retain legacy `Key_2` file support and
  reject corrupt input without replacing the last good capture.
- ARF Status **0.4.1** includes the new protocol plugin in its deployment checks.
  Standard Sub-GHz and the existing Auto Decode path can use the Europe pack;
  no new encoder or key-recovery feature is included.

F7 API remains **88.14**. **FW Packages Dev 023** remains compatible; no new
independent package revision or iOS update is required for this firmware.
Specter 3.3 stays in that separate FW Packages release. The Sub Duplicate
Finder patch is still an upstream PR, not a binary included in this release.
No saved files, user settings or pairing data are removed or migrated.

## Installation and physical acceptance

Back up `/int` and important SD files before installing this Dev build.
Install the updater package through TumoCompanion: Firmware → Dev → Beta 017,
or use `flipper-z-f7-update-t-dev-009-017.tgz` from this release.

Hardware acceptance remains open. On your own devices/captures, check Fiat V2
save/open fields and reception, Renault V1 reception/save/reopen in Europe,
Auto Decode's restoration of the original Protocol Pack, independent Standard
and Read RAW settings, and ordinary BLE/NFC/SD/FAP smoke tests. Detailed steps
are in `docs/fiat-renault-receive-followup.md`. Synthetic host vectors and CI
do not mark real receiver or physical SD tests passed.

This is a Dev prerelease for functional testing, not a stable promotion.

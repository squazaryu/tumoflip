# Tumoflip Dev 009-024

## Changes

- Standard Sub-GHz Add Manually adds **Erreka 868.35 MHz / AM650** alongside
  the existing 433.92 MHz choice. Saving and reopening preserve the generated
  seed and metadata; a failed metadata write is no longer reported as success.
- FeliCa emulation re-arms reception after malformed, rejected, wrong-IDm,
  wrong-CRC and unsupported requests. Standard Polling answers only the systems
  stored in the dump and supports directly addressed saved systems.
- FeliCa response timings use a listener-local PMm copy instead of changing the
  saved dump. Poller command timeouts follow the card's PMm and operation count.
- Extended block addresses are parsed without truncation. Addresses above the
  existing 8-bit dump model are rejected rather than accessing a different
  low-byte block. Writes validate every target before changing any block.
- Firmware API advances from **88.18 to 88.19** for an appended error-enum value;
  existing enum IDs and exported functions/variables remain unchanged.
- ARF Status **0.4.2** fixes a metadata-probe false rejection of valid FAPs with
  long C++ section names. Only the exact `.fapmeta` name is read; bounds,
  duplicate-manifest checks and the actual application loader are unchanged.

## Compatibility and package status

- No migration or breaking change: FeliCa dump format remains **4**, and legacy
  format-2/3 reads remain supported. The optional system-key-version query
  stays a late, nonfatal read pass.
- Existing API-major-88 FW Packages remain compatible. No independent package
  source changed, so a new FW Packages catalog release is not required. This
  firmware release includes its own matching manifest and package ZIP.
- No TumoCompanion/iOS update is required for these changes. Stable is unchanged.
- Back up `/int` and important SD files, including saved signals, before flashing.

## Device checks after installation

Hardware acceptance is **not run**. On your own devices/cards:

1. Confirm **t-dev-009-024 / API 88.19**, SD access, and normal BLE/App Bridge.
2. In Standard Sub-GHz Add Manually, check both Erreka frequency choices, save
   and reopen a disposable generated file, and confirm its seed/frequency/preset
   are retained. Test receiver behavior only on your own compatible equipment.
3. Read/save/reopen your FeliCa Standard and Lite-S cards/dumps; confirm PMm and
   saved systems are preserved, and repeated emulation continues after rejected
   requests. A reader/card-generation test remains necessary despite host tests.
4. Smoke-test ordinary NFC, Saved Sub-GHz playback, FAP launch/exit and reboot.
5. Open ARF Status and run Module metadata / Protocol Pack files. Confirm valid
   modules are not falsely marked invalid; Back must still cancel cleanly.

See the [hardware regression checklist](../hardware-regression-checklist.md)
and [FeliCa adaptation details](../felica-command-handling.md).

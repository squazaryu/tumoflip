# Tumoflip Dev 009-026

## Experimental Tumo RX Link for Module One

New FAP: **Apps / Module One / Signals / Tumo RX Link**.

- Receive-only timing analysis through Module One's external CC1101 and a
  separately flashed classic ESP32 backend. Not ESP32-C5.
- Histograms, min/mean/max durations, high-level time fraction and explicit
  queue-loss, missing-batch and invalid-input diagnostics.
- Local choices: 315/433.92/868.35 MHz, AM650/FM238. No new RF TX, keyfob
  emulation, credential recovery or PIN/seed search commands.
- Matching version/board/session acknowledgement is required before receive
  DMA. Old replies and incompatible firmware are ignored; link/radio loss stops
  capture and releases resources. Short and long Back both exit safely.
- All results remain in RAM. No saved signal, user keystore or SD data is deleted
  or modified by the new FAP. This is not a protocol decoder or lossless recorder.
- Native 128×64 previews cover 15 states, including failure screens and maximal
  counters, using actual draw code and firmware fonts.

## Installation — two distinct components

1. Install the normal Flipper updater. It includes the new FAP and does **not**
   flash or replace the Module One ESP32 firmware.
2. To test RX Link, separately install the optional
   **tumo-rx-link-module-one-0.1.0.zip** image on Module One's classic ESP32.
   **This replaces Marauder on that ESP32.** Retain an ESP32 backup and a known-good
   Module One Marauder restoration package first. Do not use this image on C5.

The optional ZIP is built by pinned ESP-IDF 5.3.2 CI from the exact release
commit. The embedded ESP application version must match package version 0.1.0.
Its own `rx-link-build.json` records the
source SHA, chip, exact offsets and image hashes; it is intentionally not an
automatic TumoCompanion/Marauder package. No board was flashed by the executor.
See the [backend installation and rollback boundaries](../../tools/tumoflip/esp32_rx_link/README.md).

## Compatibility and validation

- Public API stays **88.20**; private Sub-GHz ABI remains **1003**. No core runtime
  service or radio API is added. The physical flash-reserve gate remains 4096 B.
- Independent **FW Packages Dev 025 remains current**. The new FAP is firmware-
  bundled; this release has its own matching package manifest/ZIP.
- No iOS release or Stable promotion is included.
- Implementation PR #554 passed Flipper and ESP32 CI. The final implementation
  passed **1134 host tests**; shared C coverage is **100% lines / 88.78% branches**.
- Sanitizer tests include corrupt/partial UART frames, noise, bounded arithmetic,
  stale sessions, matching handshake, production frontend teardown and the actual
  ESP32 receive loop with simulated UART. These are not hardware acceptance tests.
- Publication still requires the exact version-merge rebuild, strict updater/DFU
  checks, package/import checks and downloaded asset SHA-256 comparison.

## Hardware checklist after installing

Back up `/int`, important SD files and the ESP32 before making device changes.

1. Confirm Dev 009-026 / API 88.20 and normal NFC/Sub-GHz/BLE/FAP behavior.
2. With ordinary Marauder still installed, RX Link must reject the missing
   handshake without starting RF capture. Closing the app must release the radio.
3. After explicitly flashing the experimental ESP32 image, test your own signals,
   no signal, dense noise and all four data pages. Loss must never look like a
   complete clean capture. The UART transport has finite bandwidth.
4. Test Stop, short/long Back, restart, UART/radio disconnection and reconnection.
   New sessions must reset counters and reject old replies.
5. Confirm Standard Sub-GHz can reacquire the radio after exit. Restore and check
   Marauder separately if returning to normal board use.

**Hardware acceptance and independent agent review remain unperformed.**

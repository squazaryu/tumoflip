# Tumoflip Dev 009-027

## Changes since 009-026

- **Nice O-Code 72-bit:** new Nice O-Code One entry in Standard Sub-GHz / Add
  Manually, including advanced serial/button/counter/installer-code input.
  Old selection IDs and the 52-bit API remain intact.
- **Nice O-Code 1.2:** capture/export keeps the supported long-frame shape,
  rebuilds the matching Nice One tail, and shows 72-bit O-Code under its correct
  name. Received 112-bit frames remain RX-only; export uses the supported 72-bit
  form. Existing saved signals are never overwritten by export. A failed export
  removes only a new file created by that operation.
- **Garage Door Remote 2.8 / RX-only ProtoPirate 3.2.2:** settings codecs are
  loaded only for load/save and immediately released. The settings view is
  detached before freeing and recreated on re-entry. A missing/incompatible
  codec leaves defaults in RAM but cannot overwrite the existing settings file.
  ProtoPirate retains our backup/rollback implementation.
- No Pandora emulation, unlock sequences, new brute force, new RF frequencies
  or duplicate Standard UI. These are selective adaptations, not full upstream
  ProtoPirate 4.1 parity.

## Compatibility and installation

- Local public API **88.21**; private Sub-GHz feature ABI **1003** unchanged.
  This is our own API history, not upstream number parity.
- Install the normal updater through **TumoCompanion / Firmware / Dev**. It
  includes the matching FAP/FAL resources; this release also has a matching
  `tumoflip-packages.json` and ZIP. Do not mix new apps with older firmware.
- Independent **FW Packages Dev 025 remains compatible**: its Quac/Weather delta
  does not replace these new app paths. No separate catalog or iOS release is
  needed for this firmware change.
- **Module One / RX Link is unchanged.** This updater does not flash ESP32 or
  replace Marauder. The optional experimental classic-ESP32 backend 0.1.0 stays
  on the [009-026 release](https://github.com/squazaryu/tumoflip/releases/tag/t-dev-009-026),
  with its original source metadata and hashes. It is not for ESP32-C5.
- Stable is not promoted. Back up important SD files and `/int` before updating.

## Verification

Implementation PR [#556](https://github.com/squazaryu/tumoflip/pull/556) passed
1143 host tests, native ASan/UBSan regressions and the F7 CI gate. Its physical
C2 reserve is 4096 B. GDR code/constants shrink by 888 B and RX-only ProtoPirate
by 392 B relative to 009-026; these are loaded-section comparisons, not measured
peak hardware RAM savings. Core code/constants grow by 248 B.

The release requires an exact version-merge rebuild, full host/native artifact
tests, updater/DFU/manifest validation at the 4096-byte reserve gate, and download
verification of every published asset. No installed-device success is inferred.

## Hardware checks after installation

1. Confirm Dev 009-027 / API 88.21. Check Saved/RAW, NFC, BLE Remote and normal FAPs.
2. On your own Nice remote/receiver, test 52/72-bit save/reopen, existing
   FloR-S/Nice One files, advanced creation, missing rainbow table and cancelled
   save. Confirm existing recordings remain unchanged.
3. Enter and leave settings repeatedly in both GDR and RX-only ProtoPirate.
   Check frequency/preset persistence and missing-codec failure behavior on a
   disposable copy of assets, never by deleting user recordings.

Hardware RF/SD acceptance and independent agent review remain unperformed.

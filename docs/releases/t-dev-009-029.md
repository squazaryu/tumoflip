# Tumoflip Dev 009-029

## Changes since 009-028

- **Idle out-of-memory diagnostics:** retain the failed allocation size, free
  heap, largest free block, uptime and a bounded thread-name prefix before
  verbose crash logging. The retained record survives reboot and dismissal of
  the crash popup. Existing crash records remain readable; system/PIN RTC words
  are not changed. This improves the next incident report, **not a claim that
  the cause of the earlier idle crash has been identified or fixed**.
- **Bluetooth service stack:** increase BtSrv from 1 to 2 KiB after observing a
  small stack watermark on the connected device. This uses approximately 1 KiB
  more runtime RAM; it is separate from the firmware's physical flash reserve.
- **FatFs/exFAT:** correct fragmentation state, reopening/truncating contiguous
  files and directory growth. This is not proof of what removed historical
  user recordings, and it does not recover deleted files.
- **LF RFID:** shared, byte-equivalent T5577/EM4305 request filling; bounded
  weak/skewed FDX-B reception; manual, CLI and RAW 134.2 kHz and an additional
  automatic-read step. Existing protocol/target IDs remain stable.
- **RFID/iButton screens:** fit explicit text lines to their available width,
  without changing the actual saved filenames or paths. Existing popup users
  retain their old behavior unless they opt into the new width setting.
- **Sub-GHz Remote:** adapt held/released frame completion and RAW EOF handling
  to the radio broker, stop the old mapping before switching, preserve button
  and Repeat values, and avoid extra RF transmissions during cleanup.
- **Recoverable signal saving:** checked backup, byte counts, flush/close and
  read-back verification for Remote and Quac. Failed saves attempt rollback
  and retain a verified backup. This is **not atomic power-loss protection**.
- **Quac 0.12.1:** adapted hold/release and cancellable waits are delivered
  separately through **FW Packages Dev 026**, not a Community overwrite.
- Selected official Infrared/updater message corrections are included.

## Compatibility and installation

- Public F7 API **88.22**, with the additive `popup_set_text_width` export.
  Private Sub-GHz feature ABI remains **1003**. No fake compatibility exports,
  decimal-parser behavior cuts or new automotive brute-force scenario is added.
- Back up important SD files and `/int` first. Install **TumoCompanion →
  Firmware → Dev → 009-029**, then **FW Packages → Dev 026** for the updated
  Quac. Older independent Dev 025 packages remain ABI-compatible.
- The updater includes matching firmware-baseline resources and the release
  provides their manifest/ZIP. The independent package overlay changes only
  Quac; all other Dev 025 package members are retained.
- No iOS release is required. Schema-1 crash reports keep the existing
  `kind=other` vocabulary and add `reason=oom` plus optional metrics. Current
  Companion still accepts the basic record; use **`tumocrash show`** over USB
  for the expanded fields. The current phone UI does not display those metrics.
- Module One / RX Link and ESP32-C5 firmware are unchanged. Nothing in this
  updater flashes ESP32 or replaces Marauder. The optional experimental
  classic-ESP32 RX Link backend retains its original identity on
  [009-026](https://github.com/squazaryu/tumoflip/releases/tag/t-dev-009-026).
- Stable **v1.0.8** is not promoted or overwritten. This remains a Dev build.

## Verification boundary

Implementation validation passed **1174 host tests**, native ASan/UBSan
regressions, all 20,480 old/new RFID request comparisons, 12 native-font
RFID/iButton screen states and metadata checks over **298** built FAP/FAL files.
The OOM recorder/hook/formatter are exercised against the actual 20-word RTC
layout, legacy data, interrupted writes, capacity limits and no-current-task
startup. Final publication requires the exact version-merge rebuild, repeated
strict **4096-byte physical C2 reserve** validation, CI and downloaded-byte
verification for every release asset.

No hardware OOM injection, firmware/ESP32 installation, RF acceptance or
independent agent review is claimed. The cause of the old idle OOM is unresolved.

## Checks after installation

1. Confirm **009-029 / API 88.22**. Smoke-test Saved/RAW, NFC, BLE Remote and FAPs.
2. Install FW Packages Dev 026 and check Quac on copies of your own recordings:
   hold, release, RAW completion, Back cancellation and saved Repeat/button state.
3. Check LF RFID manual/auto/RAW 134.2 kHz on your own FDX-B tags and existing
   T5577/EM4305 writing workflows on disposable owned tags. Check long status
   labels on the physical LCD.
4. Test your own static/dynamic/RAW Remote mappings and save/reopen disposable
   copies. Never use the only copy of an important recording for failure tests.
5. Leave the normal desktop idle, including your usual phone Bluetooth usage.
   If it crashes again, photograph the message and preserve the journal;
   `tumocrash show` should now provide the bounded OOM context. Do not deliberately
   exhaust memory or clear the record before it has been collected.

# Tumoflip Dev 009-030

## Changes since 009-029

- **Field wallet / Device Library 1.1:** named actions for existing SUB, IR,
  NFC, LF RFID and iButton files, with up to eight actions per object and sixteen
  pinned objects. Empty action labels fall back to the original filename. Editing
  controls are separate from quick actions; unsaved changes cannot be bypassed
  by stale menu events. Removing a link or pin never deletes its capture file.
- **Safe native opening:** NFC/RFID/iButton actions enter a saved-file menu,
  not automatic emulation. RFID/iButton inspect support requires matching native
  resources (version1.1, targetF7 and compatible actual API). Missing/old drivers
  fail closed. Normal legacy launches and RPC behavior are retained.
- **Checked wallet storage:** legacy cards open without automatic rewriting.
  Save uses checked rotating TDC2 revisions with optional action labels. Sync,
  close and exact generation/SHA256 readback must pass; errors retain the prior
  valid revision. Pins have separate checked records; confirming a removed pin
  cannot unexpectedly pin it again after a state refresh.
- **Nice O-Code 1.4:** selectively adapt Unleashed6dcf8b8 to keep plain counters
  separate from their on-air permutation in existing52/72-bit paths. Existing
  saved Key bytes remain readable; literal modes, overrides, wrap and normal
  FloR-S/One behavior are preserved. No112-bit TX, enrollment or additional
  key-search feature is added.
- Share the bounded private FAP metadata reader with ARF Status and deduplicate
  Nice setup code, retaining the full physical4KiB C2 reserve without removing
  functionality or public exports.

Implementation: [PR563](https://github.com/squazaryu/tumoflip/pull/563).
See [field-wallet behavior and limits](../product/field-wallet.md).

## Installation / compatibility

1. Back up important SD files and object-card data.
2. Install **TumoCompanion > Firmware > Dev > 009-030**, including matching SD
   resources. This updates the native RFID/iButton and Nice O-Code applications.
3. Update **FW Packages > Dev027 > Base** for Device Library1.1. The independent
   overlay changes only that FAP; the history FAL/private ABI2 is unchanged.

Public API stays **88.22**, private Sub-GHz feature ABI **1003**. Existing026
packages remain ABI-compatible. Device Library is package-only, not resident UI
or a Community Pack overwrite. No iOS or ESP32 update is required. Stablev1.0.8
and the Stable package channel are unchanged; no device is flashed by publication.

**Downgrade boundary:** Device Library1.0 cannot read new TDC2 revisions. Do not
downgrade it after saving cards without retaining your own card-data backup.
Simply opening old cards does not rewrite them. The original capture files are
not moved, renamed or deleted by this feature. Rotating records are not a backup
against SD-card failure or global atomic protection against arbitrary writers.

## Verification boundary / checks on the device

Candidate checks: **1188 host tests**, native ASan/UBSan regression fixtures,
all298 built FAP/FAL metadata checks and48 production-font GUI previews. Wallet
backend coverage:94.56% lines /91.07% regions. Publication additionally requires
the exact version-merge build, strict4096-byte physical C2 validation and
downloaded-byte checks for every release asset. Independent agent review and
physical-device acceptance are not claimed.

After installation, open an old card, add/rename/save actions, pin/unpin and
reopen the FAP. Verify that owned NFC/RFID/iButton files open their saved menus
without automatic emulation, missing files/drivers show an error, and removing
a link/pin leaves the original capture intact. Test Nice only with your own
compatible receiver. The old idle-OOM cause remains unresolved; retained
diagnostics from009-029 are preserved, not presented as a confirmed fix.

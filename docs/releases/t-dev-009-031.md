# Tumoflip Dev 009-031 — Desktop OOM recovery

## Changes since 009-030

- **Recoverable animation-frame allocation:** a large frame bundle no longer
  resets Desktop merely because free RAM is fragmented. Optional frame buffers
  can return an allocation failure instead of taking the fatal malloc path.
- **Safe fallback:** retain the fast bundled-animation path and legacy frame
  files. If external frames cannot load, the existing built-in animation is used.
  The next successful selection can load the external animation again. Animation
  files, user choices and saved captures are not removed or globally disabled.
- **Complete cleanup:** release loaded frames as well as metadata when an
  animation fails late in parsing. Partial legacy-frame failures also clean up
  every allocated buffer without turning that optional failure into a reset.
- **Mandatory allocation policy unchanged:** normal malloc still reports OOM
  with the original request. Zero/overflow/ISR rules, protected-heap locking,
  zeroing, statistics and coalescing remain. The new helper is private, with no
  SDK export. Playback/resume and shortcut-retention UI code are unchanged.

Implementation: [PR565](https://github.com/squazaryu/tumoflip/pull/565).
See [behavior and verification boundaries](../desktop-oom-fallback.md).

## Install

Install **TumoCompanion > Firmware > Dev > 009-031** normally. No Flipper or
ESP32 is automatically flashed by publication.

**FW Packages027 and the current iOS app do not need updating or reinstalling
for this fix.** Public API remains88.22; private Sub-GHz feature ABI remains1003.
All121 managed-package payloads in the implementation candidate match030 bytes.
Device Library1.1 remains available separately through FW Packages027 as before.
Stablev1.0.8 is not promoted or replaced. New Nice/Seed Capturer/Marauder upstream
changes are not included in this narrowly scoped patch.

## Verification / acceptance

Implementation validation: **1196 host tests** and native ASan/UBSan fixtures
using the actual protected FreeRTOS allocator, Desktop loader, cache and idle
selector. Regression shape:35268 requested,100448 free,31784 in the largest block.
Coverage of seven matched production bodies was91.81% lines /90.54% regions,
excluding fixture allocator stubs. Cases cover normal load, fragmented failure,
built-in fallback, retry/reload, cleanup, corrupt/partial reads and allocator rules.

Publication additionally requires exact version-merge rebuild, all FAP/FAL/API/
SDK checks, strict4096-byte physical C2 reserve and downloaded-byte verification
of every release asset. No intentional OOM is injected on physical hardware.
Independent agent review and long-idle hardware acceptance are not claimed.

After installing, check normal animations, lock/unlock and return from an app.
Then leave the ordinary desktop idle through your usual overnight/day-long use,
including your normal phone connection pattern. A brief test does not certify
week-long stability or eliminate unrelated OOM causes.

The old retained crash record may still be readable: dismissing its popup does
not acknowledge it. A new incident must be identified by its sequence/build and
fresh symptoms. If another crash occurs, preserve the photo and `tumocrash show`
before clearing or reinstalling; this patch addresses the identified optional-
frame failure, not every possible memory failure in the firmware.

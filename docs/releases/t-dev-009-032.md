# Tumoflip Dev 009-032 — Field Kit

## Changes since 009-031

- Nice O-Code: asymmetric counter conversion and upstream `No_IC` saved-file
  compatibility without weakening explicit unknown-state checks. Existing
  52/72-bit scope and saved payload bytes remain intact.
- Ten lazy receive-only protocol leaves selected from ARF: X10, Urmet, GM V0/V1,
  Toyota V0, Mazda V2, Mercedes V0/V1, Opel V1 and BMW. Existing Toyota/Mazda
  equivalents are not duplicated. Long saved payloads retain their second word.
  No new automotive encoder, enrollment, key/seed brute force, relay or jammer.
- TumoSpectrum3.4: bounded peak history and broker-owned INT/EXT dual-radio
  sweeps, with single-radio fallback and external-loss/error cleanup.
- Device Library1.2 and separate Field Tools1.0: manual object rounds with
  notes/results, verified copy-only portable objects, and explicit read-only
  capture inventory/baseline comparison. Opening an action never marks PASS.
- Experimental Passive NFC Sniffer1.0: bounded ISO14443-A candidate-frame
  capture, exclusive resource ownership/cancellation and manual verified trace
  saving. No RF field generation, relay or key-recovery tooling.
- ARF Status0.4.3 diagnoses all42 protocol leaves. Native catalog routing
  explicitly permits the new leaves without rebuilding unrelated applications.
- Local F7 API88.23 adds only `furi_hal_interrupt_try_set_isr`; equal upstream
  API numbers do not imply identical exports. The physical C2 reserve stays at
  least4096 bytes. No functionality was removed to claim free space.

## Install and compatibility

Back up `/int`, important SD files, object cards and recordings first.

1. Update TumoCompanion to **1.11.32 (285)** for managed-app protection/API guards.
2. Install **Firmware > Dev > 009-032**, including its native resources.
3. Refresh **FW Packages > Dev028** and install affected Base, Module One,
   ARF and Protocol Pack groups. Catalog revisions are cumulative.

Firmware publication and the independent package catalog are separate; use
their release pages for availability. No ESP32 board or Flipper is flashed by
publication. Stablev1.0.8 is not promoted or overwritten.

Old object cards remain readable. Portable imports create a new card and separate
capture files; they do not overwrite recordings. Export copies with an SD reader
or USB SD mode. Companion Files uploads copies back but has no generic download
action. An inventory is not a backup and cannot recover missing file bytes.
Failed imports may leave only new unpublished copies in their imports directory.

## Checks and remaining acceptance

Implementation passed1227 host tests, native ASan/UBSan fuzz/bounds/storage/resource
fixtures and F7 CI. Forty-one stock-GUI preview states include long names,
errors, input and scrolling. The four new storage/processing engines measured
93–98% line coverage; this is not coverage of the whole firmware or RF hardware.
The final release additionally requires exact merged-source build, strict C2/
DfuSe/SDK/archive/recursive metadata checks and downloaded-asset verification.

Physical acceptance remains pending: own recordings/remotes, INT/EXT/dual sweep
and unplug handling, round resume, disposable-object import, inventory comparison,
NFC reader/card placement, cancel/no-field/busy/overrun cases and native NFC after
exit. Passive NFC remains experimental. Source recordings are never deleted by
these new tools. Earlier idle-OOM/BLE reports are not declared resolved by this
feature release. Independent agent review was not performed.

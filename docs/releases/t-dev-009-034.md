# Tumoflip Dev 009-034 — NFC, RX memory and browser stability

Development build for hardware testing, not a Stable promotion. Public F7 API
stays **88.23**, with the full **4096-byte physical C2 reserve** required.

## Changes since 009-033

- NFC Ultralight rejects access starting at the exact end page, retaining I2C validation.
- CAME TWEE rejects invalid parcels; Ansonic filters slow Nice-like false positives.
- Corrected Dooya upload length, CAME Atomo / Power Smart / Somfy Keytis buffer sizing and exact Atomo/Somfy frame lengths. Captured Dooya commands and saved-file handling are preserved.
- BinRAW allocates its 10 KiB payload only when used, with nonfatal failure/retry. Disabled RAW is not armed by RSSI in Standard, diversity, ARF or Wardriving. This is RAM saving while unused, not a guarantee that every historic idle OOM crash is fixed.
- Wardriving accounts for fragmented heap and RAW serialization headroom. Existing history capacity, broker, GPS math and decoder set remain; no new eviction loop or SD deletion.
- Shared private Manchester timing conversion retains all symbol/error behavior while recovering flash space. No new SDK export or API bump.
- File browser icon/selection/null guards, compressed-text baseline and long UID confirmation fixes from PR573.
- Favorites updates use a transactional native FAL writer. Missing resources fail closed; user lists are retained on errors.

The same source prepares **USB CD-ROM 0.2** as an independent **FW Packages
Dev031 Base** overlay. It exposes an explicitly chosen ISO read-only, with
bounded SCSI/BOT handling and USB profile cleanup. No ISO images or user-data
cleanup are shipped. This app is not installed by firmware flashing alone.

## Install / migration

1. Back up `/int`, important SD files, recordings and user app data.
2. Install **Firmware → Dev → 009-034**, including native resources. Those resources deliver the updated ARF/Wardriving FAPs and favorites writer.
3. Refresh **FW Packages → Dev031** and install **Base** for USB CD-ROM. Existing groups remain cumulative; unchanged Module One and Protocol Packs do not require a new installation just for this release.
4. Existing **TumoCompanion 1.11.32** can install these releases. Before using Community Apps, manually protect the names **usb_cdrom** and **archive_favorites**, or install the forthcoming iOS protection patch when it is published. The fix is merged in iOS source but was not part of the published 1.11.32 binary. No ESP32 update is required.

There is no schema-breaking migration, automatic device flash, SD cleanup or
replacement of user recordings. Stable and historical releases stay unchanged.
No new forced KeeLoq resync, password-sniff, key-recovery database or brute-force
feature is introduced. Larger upstream ARF/history refactors remain deferred.

## Verification / device acceptance

Implementation PR573 and PR574 are merged. The source-integration batch passed
1290 host tests with fatal ASan/UBSan. Release publication additionally requires
an exact merged-version build, ELF/DfuSe/C2/resource/archive/FAP checks, green
required CI and downloaded-byte verification. See `docs/upstream-2026-11-02.md`
for exact upstream boundaries and exclusions.

After installing, test owned Ansonic/CAME/Dooya/Power Smart/Somfy samples, saved
BinRAW display/replay, RAW on/off and Standard diversity, Wardriving stop/reopen
and GPS modes. Check browser navigation, long UID confirmations and favorites
add/remove under ordinary and SD-error conditions. Test USB CD-ROM on a spare
host/ISO, including host eject, cable removal and exit; its app menu is
**Apps → USB → USB CD-ROM**. Confirm user files/recordings remain intact.

Host tests and CI do not establish physical RF/USB acceptance. Independent
agent/human review and hardware acceptance are not claimed.

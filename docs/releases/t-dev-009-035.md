# Tumoflip Dev 009-035 — automatic hopping profile fix

Development build for hardware testing, not a Stable promotion. Public F7 API
stays **88.23**. The full **4096-byte physical C2 reserve** is required.

## Changes since 009-034

- Standard Sub-GHz automatic **Preset** and **Combined** hopping excludes the
  app-owned TumoHonda RX profile, matching the ordinary modulation picker.
- Explicit **Honda 433 / Honda 315 RX**, frequency-only hopping and explicit
  hopping lists retain their behavior, including list order and duplicates.
- User-defined presets are preserved, including a custom preset whose name
  collides with TumoHonda. Runtime TX-power edits do not accidentally re-enable
  the app-owned profile in the automatic cycle.
- Private RX-profile registration is shared rather than duplicated. Public
  SDK exports and API are unchanged; no functionality is removed to save space.

No preset table, settings file, saved signal or other user data is deleted,
reordered or migrated. ARF's separate hopping behavior is unchanged. All
009-034 NFC, RX-memory, browser and favorites changes are retained. This release
does not establish the cause or resolution of every historical idle OOM crash.

## Install / compatibility

1. Back up `/int`, important SD files, recordings and app data.
2. In TumoCompanion, refresh **Firmware → Dev** and install **009-035** with
   native resources. No factory reset or SD cleanup is needed.
3. Keep **FW Packages Dev031** and **TumoCompanion 1.11.33**. If they are already
   installed, no package reinstall or iOS update is required for this patch.
   Older installations should follow the 009-034 / Dev031 installation notes.
   No Module One, ESP32-C5 or other ESP32 image update is included.

Stable, earlier Dev releases and independent package catalogs remain unchanged.

## Verification / device acceptance

Implementation PR576 is merged. Its source passed **1298 host tests**, including
native C hopping/profile cases with fatal ASan/UBSan. Native coverage of the
tested hopper/init code was 100% lines. Publication additionally requires a
clean exact merged-version build, complete tests, ELF/DfuSe/C2/resource/archive
checks, all built FAP/FAL metadata checks, green required CI and downloaded-byte
verification. See `docs/hopping-rx-profile-filter.md` for the filter boundary.

On the device after installing:

- Start **Standard Sub-GHz → Read**; cycle automatic **Preset** and **Combined**
  hopping. TumoHonda must not appear in the automatic preset cycle.
- Check an explicitly selected Honda RX profile, then return to ordinary RX.
- Check frequency-only hopping and any deliberately configured hopping lists;
  they must keep the selected modulation/list order.
- Check user custom presets, RSSI hold, stop/restart and (if used) AUTO diversity.
- Confirm saved signals and settings are still present and usable.

No physical device is flashed by publication. Hardware acceptance and
independent agent/human review are not claimed by host tests or CI.

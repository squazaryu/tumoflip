# Tumoflip Dev 009-036 — GUI refresh and defensive IR

Development build for hardware testing, not a Stable promotion. Public F7 API
stays **88.23**. The full **4096-byte physical C2 reserve** is required.

## Changes since 009-035

- Covered ViewPorts coalesce redundant redraw requests; uncovering a view
  still forces a redraw. Menu-label scrolling timers run only while entered.
- BLE connection and SD mounted/error changes explicitly refresh status icons,
  preserving our App Bridge transfer-wave and beacon widths. This does not
  change the Bluetooth connection channel or establish an idle-OOM repair.
- Unknown button names, empty databases and invalid universal IR records return
  normal errors rather than relying on release-disabled assertions. Valid
  databases retain names, offsets and EOF behavior; no file writes are added.
- A separate core unit-test build works without returning JavaScript to the
  firmware. All eight historical JS fixtures remain preserved as source-only,
  not claimed as executed coverage. Diagnostic firmware is not installed here.
- SDK documentation parsers are patched with strict audits; documentation and
  fresh packed SDK/wizard consumers are checked separately on Node 22 and
  Node 18.12/22. No new npm package is published by this firmware release.

Public API and package ownership are unchanged. No settings, recordings or SD
files are deleted or migrated. Retained Apps cache PR1195 and deferred Desktop
retained-frame work #228 are not included. The 009-035 Honda hopping fix remains.

## Install / compatibility

1. Back up `/int`, important SD files, recordings and application data.
2. Refresh **Firmware → Dev** in TumoCompanion and install **009-036** with
   native resources. No factory reset, SD cleanup or diagnostic image is needed.
3. Keep **FW Packages Dev031** and **TumoCompanion 1.11.33**. Existing installations
   do not need a package reinstall or iOS update for these internal changes.
   No Module One, ESP32-C5 or other ESP32 image update is included.

Stable, earlier Dev releases and independent catalogs remain unchanged.

## Verification / device acceptance

Implementation PR578 is merged. Its source passed **1328 host tests**, SDK/docs
and packed-runtime checks, normal and separate diagnostic builds, CodeQL and
an independent source review. Publication additionally requires a clean exact
merged-version build, the full suite, all built FAP/FAL metadata/import checks,
ELF/DfuSe/C2/resource/archive validation, green required CI and downloaded-byte
verification. Source tests and CI do not establish hardware acceptance.

After installing on the device:

- Open, scroll, leave and reopen menus/Settings and an IR button menu; labels
  must scroll while visible and redraw correctly on return.
- Connect/disconnect BLE on a static Desktop and observe the connection icon;
  install a small package to check the App Bridge transfer indicator.
- Check SD mounted/error/recovery icons using a test card or backed-up data.
- Check display streaming and returning from direct drawing or a FAP.
- Open a known-good universal IR database; malformed/unknown-name databases
  should report an error, not crash. Use copies/test data for negative cases.
- Confirm saved signals/settings remain and automatic hopping still excludes
  the app-owned TumoHonda profile while explicit Honda RX remains available.

No device is flashed by publication. Independent source review covered the
functional patch; no fresh independent release review or physical-device test
is claimed for the version-only publication work.

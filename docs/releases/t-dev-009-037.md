# Tumoflip Dev 009-037 — static decoders and external Freezer

Development build for testing on the user's own devices, not a Stable promotion.
F7 API stays **88.23**; require the full **4096-byte physical C2 reserve**.

## Changes since 009-036

- Marantec24 encoder and decoder agree on the inter-frame gap while preserving
  the measured captured-signal range.
- Linear Delta3 clears completed-key state and sends four default repetitions
  so a complete confirming pair survives the actual TX middleware.
- Holtek HT12X reset clears its prior-key confirmation state; a new capture
  cannot be confirmed against an old key from before reset.
- CAME TWEE requires the known frame prefix and retains our stricter invalid
  parcel rejection, reducing false positives without changing saved files.
- Freezer433.92MHz OOK/24-bit is a bounded external FAL in **Protocol Pack Core**.
  It is not a new modulation or a new resident decoder. Overlong frames and
  short encoder buffers are rejected. Its required private common helpers link
  inside the FAL; all imports resolve through the existing public SDK.
- The separate diagnostic runner reports empty, interrupted, missing/failed-load
  and locked runs as incomplete/failed, aggregates suite failures and frees each
  suite. Custom FAAC, Kia and loading regressions are preserved. File-reader
  wait markers are skipped and encoder test timings are merged like the radio.
- Binary validation now checks all43 protocol FALs against the public-only
  resolver, separately from feature plugins using their private host table.

All 009-036 GUI/IR fixes and prior Honda hopping fixes remain. No public decoder
struct extension, API bump, JS runtime, broad Remote Analyzer, dynamic Nero,
password-sniffing/key-recovery import or SD recording deletion is added.

## Installation

1. Back up `/int`, important SD files, recordings and application data.
2. In TumoCompanion refresh **Firmware → Dev**, then install **009-037 with native
   resources**. A DFU-only update does not deliver the new Freezer FAL.
3. Keep installed **FW Packages Dev031** and **TumoCompanion1.11.33**. The new
   Freezer FAL and ARF Status inventory are native updater resources, not a reason
   to replace the cumulative independent catalog with a rebuilt firmware snapshot.
   No package reinstall, iOS or ESP32/Module One/C5 image update is required.
4. For Freezer reception choose **Standard Sub-GHz → Protocol Pack → Core**.
   The matching file is `/ext/apps_data/subghz/plugins/protocol_freezer.fal`.

No factory reset, SD cleanup or diagnostic firmware flash is needed. Stable,
earlier Dev assets and independent catalog history remain unchanged.

## Validation / hardware acceptance

Source PR580 passed1336 host tests,270 actual FAP/FAL metadata cases, all43
protocol import contracts, normal and separate diagnostic CI and CodeQL. The
17 selected C functions have95.8–100% measured source-region coverage with fatal
ASan/UBSan. Publication also requires exact merged-version tests/build, updater
DfuSe/C2/resource/archive/SDK checks and downloaded-byte verification.

After installation, test only with owned/authorized devices or copied captures:

- Confirm Core reports Freezer loaded and re-decodes your supported RAW capture;
  check saved-file inspection and ordinary playback where authorized.
- Check own Marantec24, Linear Delta3, Holtek and CAME TWEE recordings/receivers;
  verify reset/hopping does not retain old confirmation state.
- Check other Core protocols and explicit protocol packs still load; saved files
  and settings must remain present.
- Recheck menu scrolling, BLE/SD icons and a valid universal IR database from
  009-036. This is not an idle-OOM or Bluetooth-channel repair guarantee.

The diagnostic firmware is a separate test image; ordinary publication does not
install it or execute its hardware tests. Its random-capture oracle was not
retuned without device execution. Fresh independent review and physical-device
acceptance have not been performed and are not implied by CI or host coverage.

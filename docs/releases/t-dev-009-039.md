# Tumoflip Dev 009-039 — FAAC TM and file-safety improvements

Development release for testing on owned/authorized devices, not a Stable
promotion. F7 API remains **88.23**; retain the full **4096-byte physical C2 reserve**.

## Changes since 009-038

- **FAAC TM:** static12-DIP receive/save/load/explicit send through an external
  **Core** protocol module. Exact key/width bounds, per-file timing defaults,
  matching-frame confirmation and bounded malformed-stream handling. This is
  not FAAC SLH and does not add key search or an Add Manually menu entry.
- Distinguish slower CAME12 frames from FAAC inter-frame gaps while preserving
  the legacy fast CAME path and18/24/25-bit formats. Add868.000MHz as an explicit
  selectable frequency only; default hopping frequencies/profiles are unchanged.
- **RAW Edit1.8 adaptation:** open a key input read-only and give its encoder a
  bounded RAM copy. Encoder Key/Counter updates cannot modify the original file.
  Reject imports over16KiB, insufficient heap headroom, short copies and failed
  rewinds. Load external Core formats only when needed, with ordered cleanup.
  Merge retains synthesized-frame guard metadata. This is a selective fork,
  not a wholesale upstream1.8 sync; the custom-button picker is not included.
- **Archive:** empty/unloaded selections cannot underflow the list; favorites
  reordering uses full-width indices and requires a complete list. A failed
  explicit file deletion retains its favorite and browser row. No automatic
  deletion, cleanup or user-data migration is added.
- **CLI/flash:** gpio,led,vibro,i2c handlers move to lazy native resource FALs.
  Their command behavior/flags remain; Bluetooth, crypto and recovery servicing
  stay resident. Native resource validation checks all four exact module bytes.
- **Build:** fix repeated updater/FAP distribution losing output directories or
  skipping unchanged app copies. Keep app validation and selected-target ordering.

All009-038 Hormann/KeeLoq timing and earlier functions remain. No Hiland/Phantom
keystore replacement, irreversible TM01x finalization, new GPS/JavaScript export
or previously deferred workflow is included. Source decisions and original-field
feature proposals are documented separately; proposals are not shipped features.

## Installation and compatibility

1. Back up `/int`, important SD files, captures and application data.
2. Refresh **Firmware → Dev** in TumoCompanion and install **009-039 with matching
   native resources**. Installing only the core DFU leaves the new modules absent.
3. Keep the independent **FW Packages Dev031** catalog and current
   **TumoCompanion1.11.35**. No new independent catalog revision, package reinstall,
   iOS release or ESP32 image is required. RAW Edit/FAAC/CLI changes are native
   firmware resources; reference-only catalog rows do not downgrade them.
4. No factory reset, SD cleanup, BLE re-pairing or diagnostic-image flash is
   required. Published Stable, earlier Dev and catalog history remain immutable.

The four moved CLI commands now require their SD resources; resident recovery
commands remain available without those modules. Older firmware lacks FAAC TM;
keep original recordings/RAW files if downgrading. RAW input limits intentionally
refuse an unsafe import rather than truncating or modifying its source.

## Verification and manual acceptance

Implementation [PR584](https://github.com/squazaryu/tumoflip/pull/584) passed1353
host tests, actual FAP/FAL metadata/import checks, normal/diagnostic F7 CI and
CodeQL. New native regressions run under fatal ASan/UBSan with91.95% coverage
of named production-function regions, not whole-firmware or RF coverage.
All4096 FAAC DIP values are covered by synthetic framing tests at three rates.
Repeated real-SCons graphs and actual combined firmware/FAP builds also pass.

Publication additionally requires the exact merged-version build/test/DFU,
native resource/package/SDK/archive validation and downloaded-byte verification.
Physical hardware testing and fresh independent review have not been performed.

After installation, test with owned devices or copies of captures:

- Confirm **009-039 / API88.23**, native resources and existing records/settings.
- Open an empty folder and a long favorites list; verify normal navigation.
  Exercise deletion errors only on disposable copied test files, not originals.
- Try the four CLI commands with matching resources; confirm resident servicing
  still works without SD. Do not drive GPIO on connected equipment for a test.
- Load/test owned CAME/FAAC recordings at their intended modulation/frequency.
  Check that automatic hopping has not acquired extra frequencies/profiles.
- Import a copied key file in RAW Edit, merge/save to a new file and compare the
  original's off-device digest before/after. Check oversized-input refusal.

Software validation does not establish physical receiver compatibility, explain
historic missing recordings or prove a repair of idle-OOM/BLE symptoms. No
Flipper/ESP32 was flashed and no user SD content was modified during publication.

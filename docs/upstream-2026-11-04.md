## Selected adaptations

- [Unleashed #1207](https://github.com/DarkFlippers/unleashed-firmware/commit/1cdda9a44698126ac49dab9153761762be82252d): Marantec24 uses the same15200us inter-frame gap in its encoder and RX synchronizers; retain captured15118..15188us samples inside the new window. Linear Delta3 clears the completed-frame counters and uses four default repetitions so an interior identical pair survives real TX duration merging. Holtek HT12X reset clears its preceding-key confirmation state.
- [Unleashed2e9d147](https://github.com/DarkFlippers/unleashed-firmware/commit/2e9d147ef5c4f0840f97b2980768f216edcfb60c): require the known22-bit CAME TWEE prefix before reporting54 bits. Preserve our stricter parcel0xF rejection; do not replace it with upstream clamping.
- From the same commit, adapt Freezer433.92MHz OOK/24-bit as a **Core-group external FAL**, not a resident protocol. It reuses the common handler source inside the FAL; no new public SDK symbol or decoder-structure field is added. Keep two-identical-frame confirmation; reject overlong frames before the8-bit counter can wrap, invalid pulse transitions and short encoder buffers. Check the provided RAW recording against C31C1F, plus synthetic keys, reset, noise, timing bounds and capacity limits.
- [Unleashed #1206](https://github.com/DarkFlippers/unleashed-firmware/commit/53f1ad92814d2a3f2ea66e2d78408d24adeec80f): a diagnostic run with no tests, missing suite, failed load, interruption or locked loader is not a pass. Use the existing PluginManager appid/API checks, free each suite immediately, continue collecting after a failure and aggregate counts. Reset statistics on each run and clamp a heap gain to zero leaked bytes. This code lives only in the separate diagnostic profile; its tests never run on the user's SD/device.
- Adapt only the three Sub-GHz diagnostic helpers from #1207: reset receiver state, skip worker wait markers, merge same-level encoder timings and explain failures. Preserve Tumoflip's FAAC metadata, Kia CRC, loading API tests and private FAL imports. Do not copy an upstream test file over these custom tests or guess a new random-decode oracle.

## Reviewed, not imported

- Nice RAW input-type checking from2e9d147 is already covered more strictly here:
  file header/version, RAW protocol, safe path, valid frequency and read-only
  opening are tested before starting the worker. No duplicate implementation.
- Nero Radio dynamic detection is not a small local correction: our decoder does
  not contain the upstream66-bit/trailer implementation. Porting it requires a
  separate saved-format/RAW regression boundary. Existing static Nero remains.
- The new Remote Analyzer is about7000 lines with its own protocol/radio/sweep
  lifecycle. It duplicates parts of Signal Workbench/Capture Inspector and adds
  an optional decoder get_type callback plus a public export in upstream88.24.
  Do not append that field under our unchanged ABI or bypass our radio broker.
  It needs a separate passive, package-owned adaptation before any UI import.
- No Seed Capturer, key-recovery or password-sniffing workflow is added. The
  T5577 noise-buffer change #1202 belongs to an upstream workflow previously
  excluded from this agreed scope. Existing functions are not removed.
- NFC parser-specific diagnostic fixtures from #1204 are a separate follow-up;
  this batch changes no NFC parser, NFC plugin interface or public NFC export.
- New Community SSH Runner0.3 is a GPL-3.0 UI/backend for an ESP32-S3+W5500
  add-on, not a proven Module One/C5 backend. Leave it Community-managed rather
  than copying15000 lines or claiming compatibility with the user's boards.

## Delivery and evidence boundaries

`protocol_freezer.fal` is declared in the plugin manifest, Core-group registry,
ARF Status inventory and release validator. It must be delivered with matching
resources/native protocol packs in the next separately authorized Dev/package
publication. The current immutable Dev009-036/FW Packages Dev031 do not acquire
this file from source integration. Existing shared protocol implementations
remain resident. Their helpers are not public SDK exports: the required helper
bodies are linked from shared common.c into the external-only Freezer FAL and
unused bodies are garbage-collected. Every built protocol FAL is checked against
the public-only resolver its host actually supplies. A missing optional FAL uses the existing report and
fallback path, not a fake successful load.

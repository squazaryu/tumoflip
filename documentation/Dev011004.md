# Tumoflip Dev 011-004

## Changes

- Keep the BLE bond-storage callback registered before settings reloads and
  restore it after an internal Bluetooth stack restart (PR #598).
- Add a native host regression for the complete callback-to-storage path,
  including repeated restarts, absent SD and failed writes.
- Retain the ordinary firmware, application exports and existing package
  topology. No BLE-QA profile, disabled runtime services or reduced API.
- Include the already merged Field Tools 1.1 linked-file metadata check from
  PR #598. It reports Present / Empty / Missing without reading file contents.

F7 application API stays at **88.23**. Install the matching **FW Packages
Dev035** after the firmware update; Dev034 is an exact snapshot of 011-003
and must not be relabelled as compatible with this firmware.

## Scope and acceptance

The BLE change addresses lost bond-save notifications after the internal radio
stack is recreated. It does not claim to fix every background disconnection,
connection-status UI discrepancy or iOS lifecycle issue.

This is a Dev build for testing. Native regression and release validation are
separate from hardware acceptance. After installation, pair with the owner's
iPhone, restart the Flipper normally and check that reconnection does not
request a new PIN. Existing bonds that were never saved may need one new
pairing. Keep an SD backup; no user signal or application-data migration is
part of this change.

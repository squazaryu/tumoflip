# Tumoflip Dev 011-006 candidate

Status: local candidate, not a published release. No device was flashed for
this work. Hardware acceptance is still outstanding.

## Baseline

Start from published 011-004, commit
`83f6f3a24bd25f2a2b3726d5920e4c2d30e12d2c`. Do not carry 011-005 runtime
changes into this candidate. Desktop, animations, service startup and library/compiler settings
remain those of 004; the Panel/activity/recovery changes and resident-library
LTO experiment from the rejected 005 are not included.

The rejection of 005 is not a diagnosis or a verified fix of its boot loop.
The current candidate avoids that source delta instead.

## Included changes

- Retain the post-004 HR display label and RAW Edit 1.10 filename/loading
  improvements already accepted in PRs #601 and #602.
- Stop Storage CLI read/write operations when the host closes the session.
  Real entered bytes are retained; EOF is not written as a byte. This is the
  earlier local adaptation of official PR #4529.
- Tighten receive-only KeeLoq HR sync bands and check the combined bit period
  to reject unrelated frames. Preserve the local preamble discriminator,
  bounded bit count, duplicate filter, saved metadata and transmit behavior.
  Marginal captures outside the corrected timing bands may no longer decode;
  verify reception on the owner's own remote before Stable promotion.
- Serialize a Texkom receive window with the existing speaker mutex. A busy
  TIM16 or speaker skips the window instead of asserting; release ownership
  on success, timeout and buffer overflow. This addresses that receive-time
  resource collision, not idle OOM or the rejected 005 boot loop.
- Weather Editor 2.6 ignores a checksummed LaCrosse packet with an unknown
  message type rather than crashing. Known temperature/humidity messages
  keep their existing behavior. The decoder-only adaptation retains the
  original authorship and license; no Weather Station UI was copied.
- Shorten four internal KeeLoq log strings, retaining the button value,
  failing field or receive-only restriction, to avoid spending a flash page on redundant wording. Do not
  change the build profile or lower the 4096-byte physical C2 reserve gate.
- Retain the independent, host-only startup-vector validation from the 005
  investigation, with deterministic ELF-adapter tests. It checks initial
  stack bounds and Thumb handler addresses; this does not prove hardware
  startup or identify the cause of 005's crash.

## Delivery contract

API remains **88.23**. No iOS/App Bridge contract change is needed for these
fixes. Weather Editor remains package-only at its existing path. No app-menu
migration, signal deletion, SD cleanup or user-data migration is involved.

An eventual full FW Packages release must include Weather Editor 2.6 and RAW
Edit 1.10 while retaining Field Tools 1.1 from 004. Use a new catalog revision;
do not relabel the immutable Dev037 snapshot of rejected 005 as this build.
Firmware, catalog publication/activation and hardware acceptance are separate
steps. The firmware branch alone does not publish or activate a catalog.

## Verification

New native C regressions were run RED before each production fix, then GREEN
under ASan/UBSan. They cover sync and period boundaries, frame length/reset,
duplicate filtering, speaker contention, cleanup across receive outcomes,
all 16 weather type nibbles, checksums and null callbacks. Test transports and
RTOS/hardware operations are host doubles, not physical-device evidence.

The targeted production-function coverage run covered 190/192 LLVM regions
(98.96%). This is coverage of 14 named extracted C functions only, not a
whole-firmware or hardware coverage claim. The full host suite and final
F7 updater/C2/import validation must also pass before publication.

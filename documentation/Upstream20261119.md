2. [Unleashed PR #1219](https://github.com/DarkFlippers/unleashed-firmware/pull/1219),
   Lechnio, open head `09132444e51aecd8f2d73820de62e8380a2aa7d4` at review:
   independently reproduce and fix Feron receive integrity. The inverse-command
   check is also documented by the author's
   [rtl_433 decoder](https://github.com/merbanan/rtl_433/commit/28abd067).
   Our adaptation is receive-only: require exactly 32 bits and an inverted
   command byte, reject an overlong frame before the 8-bit counter can wrap,
   and preserve all existing encoder and saved-file bytes. We deliberately do
   **not** import the proposed automatic TX checksum rewriting. Every command
   value remains allowed; this is not a hard-coded command allowlist. The check
   does not protect the device ID, authenticate a remote, or eliminate all
   false matches. It is not a CRC.
3. [Unleashed PR #1220](https://github.com/DarkFlippers/unleashed-firmware/pull/1220),
   Lechnio, open head `7fbe1f55227ebe43cbfcf3c0dc057dacb9397a29` at review:
   reproduce a shared-file enum collision and bound persisted `IgnoreFilter`
   to the five categories actually exposed in receiver settings. Our Standard
   and external ARF hosts use the same `last_subghz.settings` v3 path and both
   need the correction. A shared compile-time mask prevents drift without a
   new ABI symbol. A reused settings object resets this field before reading;
   a failed/partial read cannot leak old or partially decoded flag bits.

These are selective adaptations under the repository's existing GPL-3.0 license,
not a claim of authorship of the upstream applications. The two open PRs are
not described as accepted upstream. No brute-force or protocol-attack feature
is introduced.

## File and compatibility boundaries

Loading settings does not rewrite or delete the settings file. The five local
ignore categories are preserved; foreign flags are discarded, not translated
into guessed local choices. Frequency, modulation, RAW profile, hopping,
protocol-pack group and protocol-name filters remain unchanged. When adding a
new visible ignore category later, update `lib/subghz/ignore_filter.h` and tests.
Neither adaptation deletes/moves saved signals, favorites or `apps_data`.

Public API 88.23, private ABI 1005, protocol enum IDs and existing FAP paths stay
unchanged. The ARF host FAP **does** change, so a later Dev publication needs a
matched FW Packages snapshot, not only a firmware binary. Existing release
assets, protected-source decisions and author pins are not advanced here.
No iOS patch is required for these decoder/settings changes.

## Executable regression evidence

`test_upstream_20261119` compiles actual production C with fatal ASan/UBSan.
The radio and connected device are never opened. FlipperFormat/storage reads
are test doubles, not an SD integration test.

- Feron: all 256 commands at three synthetic IDs, every single-bit error in
  the command/check bytes, acceptance of changed IDs, no-callback operation,
  1–320-bit lengths, parser noise and recovery after a rejected frame.
- The repository's existing `feron_raw.sub` must still decode its known frame.
  The actual encoder must emit byte-identical pulses for 2,304 valid/invalid
  saved-frame cases, without silently repairing a check byte.
- Each settings loader: all 32 local-ignore combinations against each of 32
  individual bits and an all-bits input; other loaded fields must remain
  byte-identical. Missing fields, partial reads, absent SD/file, bad header or
  version, reused state and existing RAW-profile fallback are exercised.
- `measure_upstream_20261119` gates at least 80% of named production C regions
  across the decoder and both loaders, excluding fixture/macro expansions.
  This is scoped host coverage, not whole-firmware or hardware coverage.

```sh
PYTHONPATH=.:tools/tumoflip toolchain/current/bin/python3 -m unittest tools.tumoflip.test_upstream_20261119
PYTHONPATH=.:tools/tumoflip toolchain/current/bin/python3 -m tools.tumoflip.measure_upstream_20261119
```

Full host tests, the normal packaged firmware and the separate diagnostic image
remain independent gates. A successful build is not a physical EM4305 write or
radio receive test. Before hardware acceptance, verify an owned Feron remote
and compare Standard/ARF receiver settings on a backed-up test card; do not
delete the settings file as a workaround or run unknown cleanup utilities.

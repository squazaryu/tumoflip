# Upstream follow-up — 21 November 2026

Base: Tumoflip Dev 011-002, `1867a7e6774dcf180e2164ccbb735b4526c5922c`.
This changes sources only; published firmware, package revisions and installed
files are not modified.

## Selected changes

- Bound the stock TextInput drawing window and draw the selected background
  after fitting the line. The viewport keeps the caret visible when it fits;
  it neither allocates nor copies the entire text on the GUI stack. Input
  binding bounds the initial cursor by its capacity and ignores zero-capacity
  buffers. Inspired by [Unleashed #1239](https://github.com/DarkFlippers/unleashed-firmware/pull/1239)
  (jeje77131, open at review, `11a72cc7`). The upstream patch is not imported;
  Tumoflip already had a different short-input scratch-size fix.
- Copy a bounded, terminated proposed name into existing Standard and ARF
  buffers. The original path remains intact for cancel/confirmed rename.
  [Unleashed #1242](https://github.com/DarkFlippers/unleashed-firmware/pull/1242)
  (jeje77131, open at review, `e00687e1`) describes Standard; the equivalent
  ARF source is kept consistent. No existing signal is renamed on entry.
- Include 317.000 and 336.100 MHz in the shared frequency picker table,
  from [Unleashed d21fc978](https://github.com/DarkFlippers/unleashed-firmware/commit/d21fc9789b4cb59b4157194b3297f3307986fcfb)
  (xMasterX). Preserve the 433.920 MHz default, hopping table, preset IDs,
  regional and radio TX checks. No new protocol or transmit path is introduced.

No public API or private ABI change, new FAP, application relocation, directory
cleanup, or automatic storage write. Reuse existing GPL-3.0 project terms.

## Not imported

- The merged Feron/IgnoreFilter changes are already covered by the bounded
  Dev 011-002 adaptations. Do not import upstream Feron TX byte rewriting.
- [RAW More #1221](https://github.com/DarkFlippers/unleashed-firmware/pull/1221)
  expects a path-aware RAW Edit 1.9+. Our 1.8 opens a browser and ignores the
  launch argument. A future integration needs an explicit launch contract,
  compatible resources, original-capture preservation and return navigation.
- [Settings plugins #1222](https://github.com/DarkFlippers/unleashed-firmware/pull/1222)
  change private host/module wiring. Evaluate flash, loader failure behavior
  and resource parity separately. Do not transplant the upstream plugin ABI.
- SIM800, changes to HID scripting, media client, launcher navigation and the
  pending allocator/network/history work are not included. The shared heap
  and receive-history changes require their own ownership/lifecycle tests.
- ARF `7e3d1081`, official firmware `a8a24de3`, Momentum `d3f89dfe` remain
  unchanged. Companion `83f87964` changes upstream snapshot metadata only.
- [Community Pack 21nov2026](https://github.com/xMasterX/all-the-plugins/releases/tag/21nov2026)
  resolves to `2766b3cc`. Its ABI report has 443 binaries: 397 compatible,
  41 host-contract reviews, two known import failures and three intentional
  exclusions. [Protected audit #214](https://github.com/squazaryu/tumoflip-fw-packages/issues/214)
  still fails closed on the former Community RAW Edit payload, removed in
  `bd1b44f7` when the upstream editor moved to system apps. Our RAW Edit
  stays in its own FW Packages path. No baseline or acceptance is advanced.

## Verification

The new host suite compiles the actual drawing and binding functions and the
two rename scene entry functions with fake display/storage adapters. Test
ordinary short/long and empty text, narrow and regular display geometry,
cursor positions and selection, bounded binding, existing and new file names
and unchanged original paths. The default and hopper arrays are checked from
source. These tests do not use a real SD card, radio, credentials or hardware.
The existing native renderer uses the actual firmware fonts and draw callback.

```sh
PYTHONPATH=.:tools/tumoflip toolchain/current/bin/python3 -m unittest tools.tumoflip.test_upstream_20261121
PYTHONPATH=.:tools/tumoflip toolchain/current/bin/python3 -m tools.tumoflip.measure_upstream_20261121
```

Before device acceptance, use a disposable copy of a saved signal to check
opening, canceling and saving a rename. Verify that the new frequencies are
available for receive and are not added to default hopping. Do not infer
hardware results from the host renderer, sanitizer or firmware build.

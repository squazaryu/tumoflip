## Selective official PR adaptation

[Official PR #4518](https://github.com/flipperdevices/flipperzero-firmware/pull/4518),
author **Project516**, exact reviewed head
`a4b9a5aff4311845b8952847a6a100e82ca056fc`, is **open**, not a released fix.
Its useful host-side change bounds the CLI-start wait so a silent device does
not hang developer/test tooling.

The local adaptation is not a whole PR cherry-pick:

- `FlipperStorage.start(timeout=...)` shares one monotonic deadline across
  startup settling, three reads and the handshake write.
- A read is clipped to the remaining total budget and restores its former
  transport timeout even on failure. Unrelated progress bytes cannot keep a
  CLI-start attempt alive forever.
- Existing callers that omit the startup timeout retain their previous
  behaviour. Existing transfer idle timeouts continue to extend on progress.
- `testops._get_flipper` treats its limit as elapsed seconds, starts a fresh
  connection for each retry and closes a failed connection.
- Updater/bench workflow reset changes are not imported. No updater,
  flashing command or hardware script was run.

Seventeen deterministic tests use synthetic port resolution, serial objects
and clocks. They never enumerate or open real hardware. All pass, including
default-handshake, silent/noisy device, shared budget, absent port, retry,
write-error cleanup and timeout restoration cases. Observed statement-line
coverage of changed functions: `BufferedRead.until` 28/30 (93.3%),
`FlipperStorage.start` 18/19 (94.7%), `_get_flipper` 19/19 (100%).

Run:

```sh
PYTHONDONTWRITEBYTECODE=1 toolchain/current/bin/python3 tools/tumoflip/test_cli_start_deadline.py
```

## Own function: Field Tools 1.2

Extend the existing object-round workflow rather than adding another FAP:

- **Next pending object** selects the next object without an explicit result,
  wrapping within the pinned list. Resuming/starting a round begins at the first
  pending object. A manually chosen object remains a valid starting cursor.
- The round header shows the remaining count, for example **Round: 1/4 left**.
  PASS, PROBLEM and SKIPPED are manual results, not inferred device tests.
- Navigation modifies only the in-memory selection. It does not mark or save
  a result, launch an object action, open a linked file or start radio work.
- No-pending rounds hide the action and reject stale button events. Corrupt or
  unavailable data reports an unavailable round, not zero pending.
- Keep the existing 16-object limit, saved-record layout, app ID, category and
  `/ext/apps/Tools/field_tools.fap` route. No migration or iOS patch.

The Field Tools FAP version becomes **1.2**; the core/public API stays 88.23.
Standalone `fap_field_tools` build and strict APPCHK pass. All 84 imports are
already present in Dev011-004, with the same import set as the released 1.1.
Measured external file size: **42,604 → 43,604 B (+1,000 B on SD)**. The core
firmware was not rebuilt and no new resident component was introduced.

Verification uses synthetic objects and disposable host filesystem fixtures:

- **38** combined CLI, field navigation/menu, rounds, report, delivery,
  bundle and inventory checks pass.
- Separate coverage run: 15 field-engine tests; round logic **99.17% lines /
  92.51% regions**, menu **99.28% / 95.30%**. All five measured field modules
  exceed the existing 80% threshold.
- **29 production-UI frames** rendered off-device and visually inspected,
